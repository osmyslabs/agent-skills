# Integrated feature blueprint mode

Reviewed 4 November 2026 for experimental v0.3.0. The architecture package now
contains the former standalone feature workflow, an adaptable template and a
clearly fictional payout example. Its canonical name remains
project-architecture-and-blueprint; installation needs no sibling feature skill.

The entry point selects between project governance and one business capability.
Common scope/authority rules apply to both. Feature-mode instructions preserve
capability-oriented documentation, curated significant functions, evidence
labels, concrete wiring, asynchronous continuations and change-impact analysis.
Explanation-only requests remain read-only.

## Bounded evaluation

Two fresh delegated Codex solvers received isolated synthetic workspaces, the
integrated skill and raw tasks, without expected answers, rubric, parent-project
instructions or earlier conclusions. The maintaining agent inspected reports
and code references, checked file/hash effects and reran available fixture tests.
Semantic grading is an unblinded maintainer review; the exact solver model
identifier and complete tool/network traces were not captured.

| Case | Required observable behavior |
| --- | --- |
| feature-cross-module-trace | A feature-oriented primary blueprint traces request authorization, job storage, queue, explicit dispatch and the renderer boundary. It distinguishes unused injection from a call and local fake tests from production evidence. Existing architecture/runtime/tests stay intact. |
| feature-review-readonly | An explanation of the same path and renderer change boundary appears only in the sibling handoff. No workspace file, blueprint or governance record is created or changed. |

The [machine-readable receipt](feature-integration.json) identifies actual task,
corpus, instruction and output hashes, file effects and test results. Raw local
workspaces and machine-specific handoffs remain local and are not distributed.
Current cases are in the package's evals/cases.json for independent reruns.

These are two documentation/routing cases, not a full architecture evaluation or
proof of native behavior in every host. Native Claude Code and Copilot execution
remain unverified. The earlier [quality-skills report](quality-skills.md) retains
its original v0.2.0 scope, hashes, failures and interruption.
